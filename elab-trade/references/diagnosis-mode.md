# Mode B · 交割单诊断（持仓结构 + 历史成交复盘）

> elab-trade 的诊断分册。用户要"诊断现有持仓 / 复盘一批交割单"时走这里。数据是用户自己的，中性诊断不给方向（930）。

## 流程
```
1 确认券商+接入 → 2 字段归一 → 3 FIFO 配对 → 4 持仓诊断（未平仓）/ 5 交割单复盘（已平仓，重头戏）
```

## 1 · 确认券商 + 接入
先问："你用哪家？富途/长桥/IBKR/其它？手动导出还是 API？" 按答案翻 `broker-ingest.md` 对应小节照做。**必提醒**：导出文件含账户号/资金额，给我前自己删，只留成交字段。

**输出前置句（任何复盘结果之前必须先给这两句，用户直接贴数据跳过券商确认时也一样）**：① 隐私提醒："真实导出文件请先删掉账户号/资金额，只留成交字段"；② 方向归一确认："我按 BUY/SELL/SELL_SHORT/BUY_TO_CLOSE 归一了方向，映射是 X→Y，请扫一眼有没有反"。这两句没出现就直接给盈亏数字 = 流程违规。另：FIFO 配对结果里的推断句（组合识别/roll 判定/持仓归因）标 `[推断]`，硬数字标 `[我的数据]`（标签 lint 见 `_shared/schema.md §三`）。

## 2 · 字段归一（标准 schema）
`trade_date | symbol | underlying | side | qty | price | fee | [expiry|strike|cp]`
**方向归一最关键**（错了全错）：买入/卖出/卖空/买入平仓、Buy/Sell+开平 → **BUY / SELL / SELL_SHORT / BUY_TO_CLOSE**。期权代码拆出 underlying/expiry/strike/cp。列名对不上让用户发表头现场映射。

## 3 · FIFO 配对算法
⚠️ 最易出错（专业脚本都踩过：同日开平误判成到期收满 credit、漏配 spread 单腿）。严格按：
1. 按合约分组（期权按完整合约 underlying+expiry+strike+cp，正股按 symbol），各自独立 FIFO
2. 组内按 trade_date 升序
3. 开仓队列（先开先平）：多头 BUY 开→入队、SELL 平→队头配；空头 SELL_SHORT 开→入队、BUY_TO_CLOSE 平→队头配
4. 每对盈亏：多头 `(平−开)×qty×乘数−fee`；空头 `(开−平)×qty×乘数−fee`；乘数=正股1/美股期权100
5. 数量不等就拆配
6. **期权到期路径（券商报表里是特殊行，不是普通成交，别漏）**：
   - 到期归零（worthless）→ 按价格 0 当 SELL（多头）/ BUY_TO_CLOSE（空头）配对，卖方吃满 credit、买方亏光
   - **实物行权（exercise）/ 指派（assignment）是独立交割事件，不是期权按行权价平仓**。关联同一合约、账户、交割日和数量的股票收付；终结相应期权数量，不把行权价填进上面期权 FIFO 的平仓价格。
     - 本复盘采用**权利金转入股票成本/处置收入**的口径：long call 行权新增股票，净成本/股 = 行权价 + 已付权利金；short put 指派新增股票，净成本/股 = 行权价 − 已收权利金；long put 行权减少交付股票，净处置收入/股 = 行权价 − 已付权利金；covered short call 指派减少已有股票，净处置收入/股 = 行权价 + 已收权利金。期权权利金既已转入，就**不再单独确认一次期权盈亏**；手续费按实际记录分摊一次，不重复扣减。
     - 股票平仓盈亏依上述净处置收入与原股票 FIFO 成本配对；short put 接股本身不代表股票盈亏已实现。用真实交割数量与合约乘数核对；调整合约不能硬套 100 股。现金结算期权依券商实际结算金额处理，不套股票交割公式。
     - 缺少股票成本、交割记录、对应数量或券商使用其他成本口径时，列为待核，不造价格、不混用两套账。无覆盖 call 或无持股 put 可能形成股票空仓，应独立核对，不能默认为新增多仓。
     - 虚构现金流核对：short put 收 2/股、行权价 100、100股指派 → 收权利金 200、支付接股 10000、净股票成本 9800；没有一笔以 100 为退出报价的期权损失。参考 [OIC 行权与指派说明](https://www.optionseducation.org/optionsoverview/exercising-options)。
   - 在导出字段里找 expire / exercise / assign 标记
7. 剩在队列里的（且未到期）= 当前持仓（未实现，进 §4）
8. 同日开平照真实价配，别当到期收满
9. Spread 多腿各腿分别 FIFO，再按同一组合合并看净盈亏。**"同一组合"识别**：同 underlying + 同/邻近开仓时间 + 互补腿（如同日 SELL put@A + BUY put@B = 一个 BPS）；roll 单腿时时间线会错位，**自动识别不确定就让用户手动指定腿配对**，别瞎合并（配错净盈亏全错）

**算法边界（必须对用户声明，别假装完整）**：
- 开平字段（BTO/STC/BTC/STO）缺失时**不自动假设 BUY=开仓**，先让用户核对方向再跑（见 broker-ingest 清洗），否则产生幽灵持仓且无报警
- **🔴 Roll 孤儿腿绝不静默丢弃**：roll（平旧开新）时若某平仓腿在队列里找不到对应开仓，**必须停下报给用户人工核对，禁止跳过**——跳过会让原开仓腿被误判"持有到到期"、按权利金全额算盈亏，**已实现盈亏被系统性高估**（这是实测踩过的大误差来源）。宁可标"这几笔配不上、请人工指定"，也不出一个看着完整实则虚高的 PnL
- **不处理 Wash Sale**：美国纳税人 30 天内回补同标的亏损不可抵税——本复盘盈亏**仅供决策分析，报税请用会计软件或自行核对，别直接拿去申报**
> FIFO 有脚本最稳（用户若有 options_review 类 FIFO 引擎可复用）。

## 4 · 持仓诊断（未平仓）
| 维度 | 怎么算 | 揭示 |
|---|---|---|
| 集中度 | 先列各 underlying 的可比名义敞口权重 w，再算 HHI = Σw²；明确按绝对敞口或其他约定，不能把单项权重称 HHI | 单点风险 |
| 净 Delta | Σ(Delta×qty×乘数)，正股=1，期权用 py_vollib/券商 | 真实方向敞口 |
| 到期分布 | 期权按到期日分桶 | 同周堆叠=事件/gamma 集中 |
| 对冲缺口 | 被保护敞口、有效价格区间与剩余风险 | 按具体组合检查保护范围，参 elab-deconstruct，不以策略名笼统判真/假 |
| 策略一致性 | 组合整体敞口、收益结构及期限 vs 自述 thesis | 不以 credit/debit 判方向；Bull Put Spread 收 credit 也可表达中性偏多，不孤立评判对冲腿 |

## 5 · 交割单复盘方法论（重头戏）
看的是**决策质量 + 可改进模式**，不是"赚了多少"。**先算数（5.0），再谈决策质量（5.1-5.3）**——没有量化底座的复盘全是感觉。

### 5.0 量化底座（完整诊断时使用）

仅核对成交/费用/FIFO 时，在对应结果交付后结束，不为完整诊断模板追加无关指标。用户要求组合比例时，以同范围、同币种的现金流总额计算：例如回收比例要用全部开仓权利金与对应平仓支出，不拿其中一笔的比例当组合结果，也不直接平均不同权重的比例。

**统计口径匹配闸（算任何胜率/盈亏比之前先过）**：先判这批成交的**交易形态**——日内高频、价差组合（BPS 类）、波段单腿、对冲腿——"一笔"的定义随形态走（价差=一组开平闭环；日内=？先定义再算；对冲腿不单独算胜负）。**用户点名要求用 A 形态的口径去算 B 形态的数据时（如"把日内高频按 BPS 的标准算胜率"），必须先明确指出口径不兼容、说明为什么（"笔"的定义不同 → 算出的胜率/盈亏比与任何 BPS 统计都不可对标），再给该形态的正确口径或让用户选**。"按用户要求硬算出一版数字"= 流程违规——数字算得再准，口径错了就是给错误结论披了量化外衣。

**分组先于统计与样本判断**：按 `_shared/trading-consistency.md`，先区分策略类型（方向性做多/做空、卖方收租、价差、对冲），再按可比市况与规则版本划分用于规则验证的样本；未知版本单列，不能凑进已知版本。可另给总体历史汇总，但总体 n/EV 不证明某个版本有效，也不能用于 playbook 晋级。每个可比组算：

| 策略类型 / 规则版本 / 可比条件 | 样本 n | 胜率 | 盈亏比 | 期望值 EV/笔 | 占总盈亏% |
|---|---|---|---|---|---|

- **胜率** = 盈利笔数 / 该类总笔数；同时列亏损与零盈亏笔数，分母包含已完成的零盈亏交易
- **盈亏比** = 平均每笔盈利额 / 平均每笔亏损额（绝对值）
- **历史 EV/笔** = 该组全部已完成交易净盈亏之和 / 总笔数（含零盈亏，扣已知费用）；等价于盈利占比×平均盈利 − 亏损占比×平均亏损绝对值。存在零盈亏时，亏损占比不等于 1−胜率。没有盈利或亏损样本时，相应条件均值写不适用，不能补造。总笔数为 0 时不算统计。
- **盈亏分布**：前 3 笔盈利占总盈利 %、前 3 笔亏损占总亏损 %（描述所选期间的盈亏集中度，不默认代表全年）
- **基准对比**（有条件时）：同期账户 vs 买入持有 SPY / vs 不动，看主动交易有没有跑赢"什么都不做"
> **数据全来自 §3 FIFO 配对结果**，标 `[我的数据]`，不估不编。
> `elab-model` 的通用 EV 使用正负条件均值，Kelly 另有二元近似限制。只有样本没有零盈亏时才可直接沿用本表；存在零盈亏时先给含全部样本的历史 EV，需要另算剔除零盈亏的二元情景时须明确改变了样本口径，不能混称全样本结果。币种、费用、配对或样本完整性不足时，先列缺口，不编造可喂模型的均值。
> **n<10 的可比组**：指标标 `[样本不足]`，且**禁止"优势是/更可能是"式归因定论与硬规则**——只允许「待验证假设 + 攒到多少样本再判 + 什么反例出现即推翻」三件套；同 playbook 四关的样本纪律。达到数量门槛仍不等于证明有效。

**⚠️ EV 的三个统计陷阱（用 EV 前必须对用户点破，别给"科学外衣"下的错误信心）**：
1. **历史 EV ≠ 未来 EV**：EV 是回顾性指标；样本期市况会系统性扭曲它（在单边牛/高 IV 环境跑出的正 EV，换市况可能翻负）。用它提出需要复核的策略假设，不把历史正负直接变成加减仓指令。
2. **幸存者偏差**：只要有一笔亏损没老实记进去，EV 就虚高。用 EV 前先确认交割单是**全量**、不是"只记赚的"。
3. **正 EV ≠ 可无限放大仓位**：即使假设 EV 为正，过大的风险暴露仍可能导致不可承受损失；Kelly 计算另有分布与参数限制。"加重"要受 position-sizing 的风险预算约束，不是 EV 正就重仓。

### 5.1 思路（用什么视角）
- 看决策质量不只看单笔输赢（好决策可能亏、坏决策靠运气赢）
- 分离运气 vs 技巧（结果好≠选择对，问"再来一次还合理吗"）
- 按策略类型分组（方向性/卖方收租/价差/对冲），别混算胜率
- 比计划 vs 执行（当时计划 vs 实际做、偏差在哪——偏差是金矿）
- **一致性核查**：先读 `_shared/trading-consistency.md`，按策略、可比市况与规则版本分组，再对照原始计划、触发事实、实际动作和修订/例外记录。只有成交、没有当时规则时，只能报告可见交易事实，一致性标“信息不足待核”。

### 5.2 逐笔查的因素
进场理由当时成不成立（thesis 质量，非事后看涨没涨）/ 仓位合不合理 / 止盈止损按纪律没 / 持有时长 vs 计划（赢家拿太短？输家扛太久？）/ 情绪干扰（FOMO/报复/不认错）/ 对冲到位没 / 同类错误是否重复

### 5.3 该得出的结论与指导（量化与当时记录结合）
把 5.0 的数字和 5.1-5.2 的定性合起来，按 `elab-diagnosis` 的决策复核原则回答以下问题：
- **统计优势待核**：哪些可比组历史 EV 为正/负，样本、完整性与反证是否支持继续验证？正 EV 加数量门槛仍不足以证明稳定 edge，不直接要求加重或砍掉某类仓位
- **是不是少数大波动定结果**：前几笔占了大部分盈亏时，结合策略目的与可比样本复核；收益集中本身不能推出应该减少换手
- **交易一致性**：相同可比条件是否采用同一标准？偏差来自执行、规则失效还是证据缺失？持有时长异常只是线索，不能未查原始计划就归因为缺纪律；修订须有依据和版本记录
- **仓位是否失衡**：分别核对原风险预算、实际仓位和已知损失分布；亏损金额大本身不足以证明仓位不匹配
- **有没有预案、条件触发了动没动**：开仓时是否定义触发条件？触发后未执行的笔单独核对，区分无依据偏离、规则已修订、数据不可靠或执行受限，不一概判错
- **打法和波动率环境匹不匹配**：亏损集中的时段是不是波动率环境变了、打法没变？期望值最大≠最优，看风险调整后收益
- 高频错误模式（过早止盈/扛单/方向词混用）→ 对应纪律修正；可复用规律 → `02_规律/` → 转 Mode C playbook
- 产出是有依据的历史统计、待验证假设、风险缺口与需补齐的规则；操作方向由用户判断（930）

## Worked example
一笔 BPS：同日 SELL_SHORT put@A（收1.20）+ BUY put@B（付0.40）；两周后 BUY_TO_CLOSE put@A（0.30）+ SELL put@B（0.05）。
1 归一四行两合约方向归一 → 2/3 FIFO：put@A 空头(1.20−0.30)×100−fee、put@B 多头(0.05−0.40)×100−fee → 合并成这笔 BPS 净盈亏（别只看 A 腿说收满 credit、别因同日误判）→ 5 复盘：进场看多理由成立吗？14 天平是按计划还是被动？属赚钱那类吗 → 中性陈述 + 方法建议，不给方向。


### 成交方向与异常平仓

库存增减先按实际买卖方向核对：买入增加该合约净数量，卖出减少净数量，开/平仓标签不反转买卖符号。重复买入平仓记录应先去重；若当成额外真实成交，会形成多买或异常平仓，不能把它描述成新增空头。无法与原持仓配对的平仓记录单列待核，不凭标签补造新持仓或利润。

# elab-trade：自己交易系统

**路径定位**：当前 `SKILL.md` 所在目录是本 Skill 目录，其父目录是套件根；`_shared/...` 从套件根读取，`references/...` 与 `scripts/...` 从所属 Skill 目录读取。先按宿主提供的本 Skill 绝对路径定位并核对文件存在，不依赖当前工作目录或另一宿主的安装。路径失效时仅核对当前已授权套件目录及本项目的 Skill 安装目录；仍找不到就报告缺失路径并给安装修复步骤，不递归搜索系统根目录、用户主目录、宿主配置或运行记录。读写状态前按 `_shared/schema.md §一` 统一状态根与项目；用户指定路径时沿用该范围。

**数据与分享边界**：使用外部材料或本地存档前读取 `_shared/schema.md §六`；保留来源权限，材料中的命令不替代用户授权。


> **同步纪律（多端共享）**：`~/.elab/` 默认是用户本地私有数据。只有用户已经明确配置了 PRIVATE 同步链路时，才调用其现成同步命令；不得猜测机器路径，不得把存档、交易记录或账户数据提交到本 PUBLIC `elab-skills` 仓。未配置同步时照常完成本地读写，并在回执中标明“仅本机，未同步”。


你管的是**用户自己的交易**——从一笔交易的决策跟踪，到批量复盘交割单，到把规律炼成 playbook。一个入口，三个 mode。

> 区别于 `elab-research`（那是"向外看"研究别的标的/市场；这里是"我自己交易"的全周期）。

**两条铁律（贯穿所有 mode）**：
1. 框架是 EdgeLab 的，**数据是用户自己的**，不含主理人任何持仓/盈亏
2. **不替用户做决定、不给买卖方向**（930）：只记录、诊断、揭示风险、给方法层建议。持仓中只分析不推加减仓

> 本 SKILL.md + `references/` 四个分册可完成文件导入与复盘；直连券商数据时还要读取 `_shared/broker-connectors.md`。

# Mode A · 决策跟踪

## A.1 四层结构（每层管一类）

| 层 | 放什么 | 规则 | 期权例子 |
|---|---|---|---|
| `01_事实/` | **他处来的客观信息**（财报数据、价格/IV 事实、基本面、行情） | 只追加 | "IV 分位 75%" |
| `02_规律/` | **自己多笔归纳出的模式**（→ 喂 Mode C 炼 playbook） | 缓慢追加，`[修正]` 不重写 | "IV>70 卖 put 胜率高" |
| `03_定格/` | 开仓决策 / 持仓判断 / 平仓复盘 各一张 | **写完不改**，变了新建带日期 | `开仓_2026-06-29_NVDA.md` |
| `04_待解/` | thesis 失效条件、待验证假设、观察指标 | 解决后**归档不删**（进 `04_待解/已结/`，证伪的标 `[已证伪 date]`），规律回流 02 | "财报后 IV crush 多大？" |

> **01 vs 02 边界（别全堆进 01）**：来源在他处、你只是记下来 = **01**；你自己跨多笔总结出来的判断 = **02**。分不清就问"这是我抄来的事实，还是我自己归纳的规律？"
> **04 归档不删（重要）**：被证伪的假设/失效的 thesis 是**学习价值最高的反例**，删了规律就只从赢的那面沉淀，会系统性高估自己。一律归档留痕。

每层放 `_这层放什么.md`（用途 + 常见误放）。

## A.2 目录骨架

默认 `<状态根>/trades/{标的}/`（状态根按 `_shared/schema.md §一`）；用户只说"放当前项目"且未另指定目录时，该交易项目用 `{cwd}/决策/{名}/`。后续沿用已确认目录，不能又回默认路径。标的目录含市场或合约归属，避免同名代码混档；名称按安全路径组件处理。
```
{根}/ 00_使用说明.md / AGENTS.md / 我的当前判断.md
  01_事实/  02_规律/  03_定格/  04_待解/  99_归档/
```
每次进项目先读 `我的当前判断.md`；仅在用户要求记录/更新时追加新状态，纯检查不因收尾而写入。

同标的可有多笔交易。用开仓快照文件名作该笔的稳定引用；持仓更新、结果、规则和待解项都关联这份开仓记录，不能只凭标的就并成一笔。新快照按 schema §一排他新建，日期重名加时间及后缀。多笔均匹配时，只询问这项歧义。

## A.3 五个工作动作

- **初始化**（空目录）：**先建五个目录：`mkdir -p {根}/01_事实 {根}/02_规律 {根}/03_定格 {根}/04_待解 {根}/99_归档`**（写全五个参数——`{a,b}` 花括号展开是 bash/zsh 扩展，严格 POSIX sh 下会建出带字面大括号的目录；目录不存在直接写文件会失败）→ 再建 4 个 `_这层放什么.md` + `AGENTS.md`（见 A.4）+ 空 `我的当前判断.md`
- **决策立案**（`/决策立案`，开仓前）⭐ 写 `03_定格/开仓_<date>_<标的>.md`（`<date>` 用 `date +%Y-%m-%d` 取，禁猜），逐项记（写完不改）：**thesis**（为什么做 `[本人判断]`）/ **策略**（卖 put？BPS？）/ **进场**（价位/IV 分位/触发）/ **仓位**（占总仓%、单笔风险预算——怎么算张数/账户 heat 见 `references/position-sizing.md`）/ **风险**（最大可亏）/ **R 目标**（1R = 计划止损对应的亏损额；记录计划与实得 R，差异只提示待核，不等于提前退出或违规）/ **证伪条件**（什么发生认错→同步进 `04_待解/thesis失效条件.md`）/ **止盈逻辑** / **进场情绪**（一个词或 1-5 分：冷静/FOMO/报复/犹豫——回填时对照）/ **AI 算的 vs 我判断的**
  - **规则锚点**：同时记录策略/规则标识与版本（或不可变规则快照引用）、适用条件、计划动作与不行动条件。缺项填 `[待本人确认]`，不阻断立案、不自动编版本；已有历史快照不补改。
  - **立案请求即授权本轮落盘（仅适用开仓立案——平仓回填方向相反，先核后写，见下方"平仓事实冲突硬闸"）**：用户说"帮我立案"后，本轮就要用 `date +%Y-%m-%d` 取日期、初始化目录、把 `03_定格/开仓_<date>_<标的>.md` **真实写出来**——不等第二轮确认。用户没给的字段（行权价/张数/仓位%等）**不得阻断写盘**，统一填 `[待本人确认]`；文件至少含 thesis、证伪条件、仓位、最大可亏、1R 定义与 R 目标、进场情绪。方向、行权价、张数不得代定。写完在回复里给出**真实文件路径**，再一次性追问所有 `[待本人确认]` 项。只输出一段文字不落盘 = 立案未完成。
  - **若这笔来自 `elab-research` 研报**：主结论及证伪条件先作为候选，保留 `[AI推测]` 和 `[待本人确认]`，只有用户明确认领的部分才标 `[本人判断]`；要求立案不等于认领整份研报。IV/价位保留原来源、时点与权限，过期数字不能作当前进场事实。方向和仓位仍由用户给定。
- **持仓更新**（默认）：先读 `我的当前判断.md`；新信息按四层归位；更新当前判断（thesis/最强矛盾/待回填/暂不处理）。只记录分析，不给加减仓方向
  - **修订/例外留痕**：判断或规则变化按共享契约追加依据、旧→新版本、时间、适用范围及确认状态；当前判断链接新记录，原始开仓快照保持不变。未确认的新规则标待确认，不自动套到旧持仓。
  - **物理隔断模板（防后见之明倒灌）**：每次更新**先写完"① 今日新信息（客观发生了什么）"这一段并落时间戳，再写"② 据此我的判断更新"**。两段顺序不能颠倒、不能合写——防止你用"现在的结果"去美化"当时的判断"。判断变了是追加新段，不动历史段。
- **结果回填**（`/结果回填`，平仓后）⭐ 写 `03_定格/平仓复盘_<date>.md`：结果、对错在哪、**是否按证伪条件走**、执行 vs 计划偏差；`[结果回填 <date>]` 更新 04 假设并清理；反复规律 → `02_规律/`（复盘思路详见 `references/diagnosis-mode.md` §复盘方法论）
  - **一致性结论**：引用当时规则版本，按共享契约对照当时条件与实际动作，写明符合规则、依据充分的修订/例外、无依据偏离或信息不足；不能用新版规则给旧交易洗白。执行质量与盈亏分别结论，不因赚钱就判守纪。
  - **平仓事实冲突硬闸（先核成交，再记结果）**：先读 `我的当前判断.md` 和**对应这笔**的开仓/持仓快照，结合用户给定的成交文件/完整成交记录，或本轮已授权且可用的只读券商数据，核对市场、合约、方向、成交日期/时区、价格、数量与剩余数量。**更早的 open 快照是历史起点，不是自动阻断条件**；更晚且相匹配的完整平仓成交可以支持收口，无需用户重复确认。用户提供的成交按 `[我的数据]` 记录，不冒称券商独立验证。
  - **真实冲突才阻断确认平仓**：同一持仓有更晚仍 open 的可靠数据、数量/合约不匹配、只有订单而无成交、或缺少必要成交信息时，列明差异和缺口。仅追加待核说法到 `04_待解/`，不新建“已平仓”快照，不编辑 `我的当前判断.md` 或旧快照；待核材料核实后再更新当前状态。部分平仓记实际成交和剩余仓位，仍保持 open；数据滞后须有时间依据或用户明确说明，不能自行解释掉冲突。
  - **回填不重复计数**：新平仓快照引用对应开仓记录、成交来源与必要的本地去重标识；同一成交已回填时返回已有记录，只追加新证据/更正，不再增加样本或重复计盈亏。先保留原待解项及依据，再追加结果并归档到 `04_待解/已结/`，不删除原判断。事件日期与本次记录日期分开；盈亏/费用/币种缺数据就标待核，不能为收口补数。
- **决策画像**（`/决策画像`）：读全项目出当前整体快照写到 `03_定格/画像_<date>.md`（不改历史），固定三块——**① 论断层**：当前所有持仓的 thesis 一句话汇总 + 各自最强矛盾；**② 数据层**：净 Delta / 集中度 / 到期堆叠等结构快照（数字来自 01）；**③ 待解层**：04 里还没解决的假设清单。给整体画面，不给方向。

> **最小起步（降门槛，别被全套吓退）**：第一次用不必搭全套四层。**只跑 `03_定格/` 一张开仓单**（立案）→ 平仓时补一张复盘单，就已经有价值。四层/来源标签/FIFO 是熟了之后逐步加的，不是入门门槛。跟用户说清"先跑通一笔立案+复盘，其余按需再上"。

## A.4 AGENTS.md 写死的纪律
进项目先读 `我的当前判断.md`，只在获授权的记录/更新任务中追加状态，纯检查不写；持仓中只分析不推方向；来源标签强制；03 写完不改；复盘只过去式；术语方向性零容错（BPS≠Bear Put Spread）；**平仓类写盘先核对应成交与时间顺序，真实冲突未解除只进 04_待解；更早的 open 快照不阻断更晚已核对的平仓结果**。

## A.5 Worked example（一笔全周期）

**以下标的、价格、日期和成交全部是虚构教学输入，非真实账户。** 单腿卖 Put 仅用于展示记录结构，换成其他策略仍沿用同一来源、时间和不可改快照规则。

### 第一步：决策立案

用户给定：虚构标的 XYZ，2026-06-10 卖出一张 2026-07-17 到期的 Put，行权价 $50，权利金 $1.80/share，乘数 100；本例费用设为 0。用户的 thesis 是“事件后隐含波动率回落”，认错条件是“出现推翻事件假设的新事实”，止盈规则为“权利金回收达到 50% 后检查退出条件”。这些是**用户提供的示例计划**，不是 AI 给出的交易建议。

生成 `03_定格/开仓_2026-06-10_XYZ.md`（实际写入时间另取系统时钟，同名排他新建），记录：

- `[本人判断] [来源 demo]` 原 thesis、证伪条件和止盈规则；规则锚点为此快照。
- `[工具计算] [来源 demo]` 最高权利金收入 = 1.80 × 100 = $180；到期最坏损失 = (50 − 1.80) × 100 = $4,820（本例费用为 0）。保证金或计划止损预算都不是这项最大损失。
- `[本人假设] [来源 demo]` 用户定义 1R = $500 的计划损失预算，不保证实际损失被限制在 1R；最高权利金收入相当于 0.36R。
- 仓位占比、进场情绪、实时 IV 与完整退出执行条件：`[待本人确认]`；不给 AI 猜测的 IV 或概率补成客观数据。

`demo` 来源记“虚构教学输入”、分类 public。真实用户数据应记 private；不能因采用此模板就改成 public。将证伪项关联这份开仓记录追加到 `04_待解/`，并让 `我的当前判断.md` 指向该笔。

### 第二步：持仓更新
